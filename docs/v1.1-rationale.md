# Rationale for v1.1.0 — default multi-agent adversarial review

**Status: ADOPTED in v1.1.0.** The normative text is in
[ADVERSARIAL_REVIEW.md](../ADVERSARIAL_REVIEW.md) and the bundled skill
protocol; this document records why the change was made. The issue link,
independent PR review, and NCO signoff required by
[CONTRIBUTING.md](../CONTRIBUTING.md) are still pending before merge.
Prepared 2026-11-24 from (a) [Adversarial Review: What It Means and How to Run It](https://heym.run/blog/ai-code-review) and (b) the arXiv literature catalogued in [docs/research-basis.md](./research-basis.md).

## Decision summary

| Method from the blog / literature | Verdict | Why |
|---|---|---|
| Second agent argues against the first instead of re-reviewing from scratch | **Adopt — default role** | This is the difference between our current "adversarial stance" and an actual adversarial *protocol*. arXiv:2608.18167 is built on exactly a reviewer R plus a critic C. |
| Different model vendors for reviewer and challenger | **Adopt — MUST where available** | Cross-family review catches correlated blind spots (arXiv:2604.19049). The portable rule requires different families where more than one is available and records the same-family limitation otherwise; a single-family deployment remains conforming but weaker. |
| Read the actual diff/artifact, not the author's summary | **Adopt — v1.1.0 Rule 3** | Cheap, high-value, and already implied by our evidence rule. The blog calls it load-bearing; arXiv:2608.18167 freezes the artifact during the review loop for the same reason. |
| Structured contract: finding id, severity, confidence, file:line, failure mode, fix; challenger verdict accept/reject/modify/needs-evidence | **Adopt — required structured fields** | Our prose format is human-readable but cannot be merged by a written policy. MARS (arXiv:2509.20502) and AR both use structured review fields; confidence is the missing calibration signal in our current format. |
| **Explicit disagreement types** (`DISAGREE_EVIDENCE: <code citation>` vs `DISAGREE_CONCERN: <epistemic objection>`) | **Adopt — highest-value single change** | In arXiv:2608.18167, naive AR scored F1 = 0.457 on SWE-PRBench (worst of four methods) because critics agreed with weak findings and yielded to confident rebuttals; adding typed pushback raised it to F1 = 0.533 (best). This is a direct, measured fix for a failure mode our single-agent protocol cannot detect. |
| "State what evidence would change its mind" per finding | **Adopt** | Prevents adversarial theatre and gives the arbiter a concrete test. Complements our UNVERIFIED bucket. |
| Reconciliation log: accept-and-fix or reject-with-reason for every objection, no silent drops | **Adopt** | Our UNVERIFIED rule covers unresolvable suspicions, but we have no record of *resolved disagreements*. Without one, "fix-forward" can quietly discard the challenger's good catches. |
| Written arbitration policy mapping surviving severity/confidence to approve / comment / request-changes | **Deferred — not implemented in v1.1.0** | Our file is a repo-declared contract, not a CI gate. A severity/confidence-to-merge-action template for the worked example remains future work; no mapping was added in this release. |
| Keep a human arbiter on ambiguous, high-stakes calls | **Adopt as a clarification** | The NCO signoff already exists in governance. Link it explicitly: an unresolved `DISAGREE_CONCERN` on a CRITICAL/HIGH finding goes to the NCO, not to a model vote. |
| Scope discipline: disagreement must not expand the change beyond the reviewed ask | **Adopt — new rule** | arXiv:2608.18167 case 2 shows the reviewer–critic loop turning a speculative question into an out-of-scope 32-line patch that failed hidden tests. "Fix-forward" (v1.0.1 Rule 6, now v1.1.0 Rule 7) needs this guardrail. |
| Risk-tiered depth (full pipeline only for high-stakes diffs) | **Not adopted** | The blog's expected-value argument is sound and AR uses ~4.5× the tokens of zero-shot on SWE-bench Verified, but removing the "no size exemption" rule would reopen the silent-coverage-pruning hole fixed in v1.0.1. All lenses and all three roles stay mandatory and the round cap stays fixed at five; repos may add rounds in their own rules. |
| Traces and evals to score reviewers over time | **Defer** | Infrastructure, not file format. The structured output extension is the prerequisite; add it first. |
| GitHub MCP / sequential-thinking tool wiring | **Reject for the standard** | Tool-specific; belongs in the skill and in repo-specific "commands the reviewer must run". |

## What our spec already does better than the blog's protocol

Do not trade these away when adding the loop:

- **Evidence rule and UNVERIFIED bucket.** The blog's prompt asks for severity and confidence; our Rule 3 additionally forbids promoting an unconfirmed suspicion to a finding *and* forbids dropping it. That is stronger.
- **Per-lens coverage ledger.** COVERED/SKIPPED with reasons catches silent scope pruning. The blog's pipeline has no equivalent, and arXiv:2608.18167's false-consensus cases are precisely what such a ledger helps surface.
- **The `governance` lens.** The blog audits code correctness and conventions; our governance lens checks whether the review rules themselves are enforced.
- **Repo-owned invariants.** "Read the repo's own rules" is more portable than a fixed prompt, and the AR paper's SWE-bench result shows a pure-text SKILL.md form can drive the protocol without an orchestrator.

## Evidence and counter-evidence

Supporting: arXiv:2608.18167 (reviewer + critic beats five-agent MARS on LiveCodeBench, 87% vs 82%, with three agents; highest F1 with typed disagreement), arXiv:2604.19049 (adversarial kill mandates, cold-start critics, cross-model critic), arXiv:2402.02172 (communicative multi-agent review with a QA-Checker).

Cautionary: arXiv:2311.17371 and PMLR 235 (multi-agent debate often fails to beat cheaper self-consistency/ensembling baselines and is hyperparameter-sensitive); arXiv:2508.17536 (majority voting accounts for most MAD gains; debate alone does not improve expected correctness); arXiv:2611.23283 (single-agent systems can match or beat multi-agent ones on review tasks); arXiv:2505.19477 (debate can *amplify* judge bias); arXiv:2406.07791 and arXiv:2410.21819 (position and self-preference bias in judges). arXiv:2603.15911 finds AI reviewers produce more suggestions with lower adoption rates than humans. These are why the v1.1.0 loop is structured, evidence-grounded, and human-arbitrated — not an uncritical mandate to add agents.

## Adopted text

### New section: `## Review loop` (default, not opt-in)

The loop is mandatory for every review under v1.1.0; there is no
`multi-agent: true` switch. The three roles are M (authoring agent), R
(independent reviewer), and C (challenger of R's review). R and C MUST use
different model families where more than one is available; otherwise the
same-family limitation is recorded in the report. R emits stable finding
ids, severity, confidence in [0, 1], evidence, and what would change its
mind. C emits ACCEPT / REJECT / MODIFY / NEEDS_EVIDENCE per id plus missed
issues with code citations, and labels objections as `DISAGREE_EVIDENCE` or
`DISAGREE_CONCERN`. The artifact is frozen during the inner loop (five-round
cap); every C verdict is reconciled explicitly; unresolved concerns on
CRITICAL/HIGH findings escalate to the human NCO; and fixes stay in scope.
The normative wording is in `ADVERSARIAL_REVIEW.md`, not here.

### Amendments to existing text

- Rule 3: add "Read the actual diff, commits, and artifact yourself; a summary written by the authoring agent is not evidence."
- Rule 7: add "Fixes must stay within the scope of the reviewed change; out-of-scope improvements are a separate finding, not an implicit edit."
- Output format: require `id`, `confidence`, `would-change-mind`, and a `Reconciliation` section.
- `skill/adversarial-review/SKILL.md`: spawn R and C by default; there is no `multi-agent` switch, and the bundled fallback protocol is v1.1.

## Governance status

The v1.1.0 text and version bump are published at a GPG-signed `v1.1.0` tag,
along with the bibliography and site updates. The diff was reviewed under the
v1.1.0 protocol itself in `docs/adversarial-review-2026-11-24.md` (R then C,

under `CONTRIBUTING.md` and not performed here: an accepted issue linking this
document, a PR review by a party other than the author, and an NCO signoff
comment in the required format. No signoff is implied or fabricated by this
release. The quickstart pins to the signed `v1.1.0` tag, verifiable with
`git tag -v v1.1.0`; it includes the default reviewer–challenger loop.
